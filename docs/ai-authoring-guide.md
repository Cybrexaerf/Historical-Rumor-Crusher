# 「史实勘误局」卷宗 md 编写规范（AI 投喂版）

> 本文档是完整的机器可读规范。将全文粘贴给任意 AI 助手，即可让其正确编写可被本应用直接导入的卷宗 md 文件。
> 规范与应用校验器（`src/content/schema.ts` + `src/content/parse-entry.ts`）完全一致：**凡违反本文任一硬性规则的文件都会被拒绝导入/构建失败，并返回中文错误定位。**

---

## 〇、给 AI 的角色指令（粘贴时保留）

```
你是一名历史谣言档案编撰员。你的任务是根据我提供的谣言主题与史料，
严格按照下述规范编写一份完整的卷宗 md 文件。
你必须：先读完整个规范再动笔；产出前逐项对照第十节自检清单自查；
对任何拿不准的史实，宁标注「存疑」也不虚构；所有论证必须有参考文献支撑。
```

---

## 一、文件基本要求

1. **一文件一谣言**：每个 md 文件对应一条谣言卷宗。
2. **文件名** = `id` + `.md`（如 `id: qianlong-hanrein` → 文件名 `qianlong-hanrein.md`）。
3. **文件结构**：两部分，顺序固定——
   - YAML front-matter（元数据块，以 `---` 行开始、`---` 行结束）
   - Markdown 正文（四个语义区块，见第四节）
4. **编码**：UTF-8（无 BOM），换行 LF 或 CRLF 均可。
5. `id` 一经发布**永不修改**；后续修订保持同 id、将 `revision` 加 1。

---

## 二、Front-matter 字段规范（全部必填，除特别说明）

```yaml
---
id: qianlong-hanrein
title: 乾隆是汉人陈世倌之子？
rumor: |
  乾隆皇帝并非雍正亲生，而是海宁陈家之子，雍正以女易子换入王府。
verdict: refuted
era: qing
category: royal
tags: [乾隆, 身世传闻, 海宁陈家]
origin: 文学演绎
evidence: strong
updated: 2026-08-20
revision: 1
references:
  - id: ref1
    type: ancient
    text: "（清）陈康祺. 郎潜纪闻·卷四. 北京: 中华书局, 1984: 132."
  - id: ref2
    type: modern
    text: "孟森. 明清史论著集刊正续编[M]. 石家庄: 河北教育出版社, 2000: 485-492."
---
```

### 字段逐项说明

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | string | 正则 `^[a-z0-9]+(-[a-z0-9]+)*$`（kebab-case），全库唯一 | 小写字母/数字/连字符；一经发布不改 |
| `title` | string | 1–60 字符 | 谣言的一句话概括，通常为疑问句 |
| `rumor` | string | 1–300 字符 | 谣言**原始陈述**（用 `\|` 块标量多行书写）；将渲染在「举报信」卡片中，必须是谣言本身的转述，不是你的反驳 |
| `verdict` | enum | `refuted` / `partial` / `disputed` / `open` | 已证伪 / 部分属实 / 存疑 / 无定论 |
| `era` | enum | 8 选 1，见下表 | 该谣言所指历史事件的时代 |
| `category` | enum | 7 选 1，见下表 | 内容分类 |
| `tags` | string[] | 1–8 个，每个 1–12 字符 | 主题标签；纯数字请加引号（如 `"1421"`） |
| `origin` | enum | `文学演绎` / `讹传` / `伪史` / `网络新造` / `影视误导` | 谣言的来源类型（注意是**中文值**） |
| `evidence` | enum | `strong` / `medium` / `weak` | 本卷论证的史料支撑强度 |
| `updated` | string | `YYYY-MM-DD` | 最后修订日期 |
| `revision` | int | ≥ 1，默认 1 | 每次修订内容时 **+1**；导入时用于版本裁决 |
| `references` | array | ≥ 1 条 | 参考文献，见第三节 |

### era 受控词表（8 个）

| 值 | 含义 |
|---|---|
| `xianqin` | 先秦 |
| `qinhan` | 秦汉 |
| `weijin` | 魏晋南北朝 |
| `suitang` | 隋唐 |
| `songyuan` | 宋元 |
| `ming` | 明 |
| `qing` | 清 |
| `modern` | 近现代 |

### category 受控词表（7 个）

| 值 | 含义 |
|---|---|
| `royal` | 帝王身世与宫廷 |
| `war` | 战争与军事 |
| `figures` | 名人轶事 |
| `texts` | 文化典籍与文献 |
| `tech` | 科技与发明 |
| `society` | 社会生活与制度 |
| `modern` | 近现代史 |

## 三、references 数组规范

每条引用是一个对象，三个字段全必填：

| 字段 | 约束 | 说明 |
|---|---|---|
| `id` | 正则 `^[a-z0-9-]+$`，**同文件内不得重复** | 正文用 `[^此id]` 引用它；惯例从 `ref1`、`ref2` 递增 |
| `type` | `ancient` / `modern` / `journal` / `web` | 古籍 / 近现代出版物 / 学术论文 / 网页存档 |
| `text` | 非空字符串，**必须用英文双引号包裹** | GB/T 7714 格式的完整条目（因内含 `: ` 冒号空格，不加引号会 YAML 解析失败） |

### 各 type 的 text 书写格式

**ancient（古籍，传统引法）：**
```
"（清）陈康祺. 郎潜纪闻·卷四. 北京: 中华书局, 1984: 132."
"（汉）司马迁. 史记·秦始皇本纪. 点校本二十四史修订本. 北京: 中华书局, 2014."
```
朝代加括号 → 作者 → 书名·卷次 → 点校本信息 → 出版信息。

**modern（近现代出版物，GB/T 7714）：**
```
"冯尔康. 雍正传[M]. 北京: 人民出版社, 1985: 412-415."
"孟森. 明清史论著集刊正续编[M]. 石家庄: 河北教育出版社, 2000: 485-492."
```
作者. 书名[M]. 出版地: 出版社, 年份: 页码.

**journal（论文）：**
```
"王瑞来. 烛影斧声事件考辨[J]. 中国史研究, 1998(2): 45-58."
```
作者. 题名[J]. 刊名, 年(期): 页码.

**web（网页存档，注明存档情形）：**
```
"某某网. 某文章标题[EB/OL]. (2023-05-01)[2026-08-20 存档]. "
```
> 注意：即使 type 为 web，text 中也**不得包含 http(s):// 链接**（离线铁律），用文字描述来源与存档日期。

## 四、正文结构规范

正文由四个二级标题（`##`）区块组成，标题文字必须**逐字**使用以下四个（不加编号、不加标点）：

| 区块 | 必含 | 作用与写法 |
|---|---|---|
| `## 谣言溯源` | ✅ 必含 | 谣言从何而来：最早的文字源头、谁写的、如何演变。此区块渲染为「旧闻剪报」风格 |
| `## 流传脉络` | ❌ 可选 | 谣言传播链（A→B→C 箭头式一行概括很受欢迎）。史料不足可整段省略 |
| `## 史料考证` | ✅ 必含 | **主体论证**。逐条列证据，用 `其一/其二/其三` 或有序列表组织；每个论点标注脚注引用。渲染为正文纸面 |
| `## 真相结论` | ✅ 必含 | 三五句最终裁定，渲染为墨绿「结案陈词」卡 + 评级盖章。必须与前文论证一致，不得引入新论据 |

规则：
- 除以上四个 `##` 外，不得出现其他二级标题（会并入上一区块并告警）。
- 区块内可用 `###`、列表、引用块、粗体、表格等常规 Markdown。
- 正文三级以下标题随意（如 `### 其一：时间对不上`）。

---

## 五、脚注引用规范（关键机制）

- 在正文任意位置写 `[^ref1]` 即引用 id 为 `ref1` 的参考文献，渲染为朱红上标 `[1]`，悬浮显示完整条目。
- **无需手写脚注定义**：构建器会自动把 front-matter 中被引用过的 references 生成为脚注。你只管写 `[^refN]`。
- 同一引用可多次使用（`[^ref1]` 出现多次没问题）。
- 引用了不存在的 id 会被自动忽略——所以**每个 reference 至少要在正文中被 `[^id]` 引用一次**，否则属于冗余文献（不报错，但应避免）。

---

## 六、硬性禁令（违反即导入/构建失败）

1. **禁止任何 http/https 链接**（正文中、参考文献 text 中都不行）——本应用离线运行。
2. **禁止 raw HTML**：Markdown 中的 HTML 标签会被原样转义显示（如 `<script>`、`<img>`、`<a href>`），因此毫无意义。所有格式用纯 Markdown 表达。
3. **front-matter 缺字段、值超出受控词表、日期格式错误、references 为空、ref id 重复** → 校验失败。
4. **必含区块（谣言溯源/史料考证/真相结论）缺失** → 校验失败。
5. `title` 超过 60 字、`rumor` 超过 300 字 → 校验失败。
6. **禁止虚构参考文献**（书名、作者、页码、DOI）。不确定就不写；宁可少引不可错引。这是档案馆的信条。

---

## 七、内容质量要求（AI 特别注意）

1. **rumor 字段写谣言本身**，不是辟谣结论——结论属于「真相结论」区块。
2. **评级诚实**：证据链完整且学界无争议 → `refuted`/`partial`；存在合理学术争议 → `disputed`；史料完全不足 → `open`。不要把「我倾向于认为」写成「已证伪」。
3. **部分属实要写清哪部分**：`partial` 时在结论中明确「哪一半真、哪一半假」。
4. **证据强度自评**（evidence）与实际引用质量一致：只引了二手网文 → `weak`；正史+现代学术著作 → `strong`。
5. **区分「证明为假」与「无法证明为真」**：前者是 `refuted`，后者是 `disputed` 或 `open`。
6. 考证区块中，引用原始史料（正史、原书）的论证权重高于转引；点校本信息能写则写。
7. 正文语气：克制、档案式、可核查；不用感叹号，不用「震惊」「真相竟是」等网文腔。

## 八、完整合法示例（可直接作为模板复制）

````markdown
---
id: yangguifei-dongdu
title: 杨贵妃没死，东渡去了日本？
rumor: |
  马嵬驿之变中杨贵妃并未被缢死，而是被掉包放走，经海路东渡日本，
  终老于彼，日本山口县至今有杨贵妃墓。
verdict: refuted
era: suitang
category: figures
tags: [杨贵妃, 马嵬驿, 唐代宫廷]
origin: 讹传
evidence: medium
updated: 2026-08-20
revision: 1
references:
  - id: ref1
    type: ancient
    text: "（后晋）刘昫等. 旧唐书·卷五十一·后妃传. 北京: 中华书局, 1975."
  - id: ref2
    type: modern
    text: "陈寅恪. 元白诗笺证稿[M]. 北京: 生活·读书·新知三联书店, 2001: 21-37."
---

## 谣言溯源

「贵妃东渡」的源头是白居易《长恨歌》「不见玉颜空死处」的文学留白，
以及日本中世以来流传的杨贵妃传说。日本山口县久津确有「杨贵妃墓」，
20 世纪日本作家的演义小说将其推向中文世界[^ref2]。

## 流传脉络

《长恨歌》文学想象（唐）→ 日本民间信仰与久津墓（中世）→ 近代日本小说演绎 → 中文网络「掉包东渡」故事定型。

## 史料考证

其一，正史记载明确。《旧唐书·后妃传》载：马嵬之变「上即命力士赐贵妃自尽，
遂缢死于佛室」[^ref1]，且改葬时「肌肤已坏，而香囊仍在」，可见确有尸身。

其二，陈寅恪对《长恨歌》的笺证早已指出：方士海上觅魂纯为文学虚构，
不可当史实读[^ref2]。

其三，久津「贵妃墓」经中日学者考证，实为日本古代杨贵妃信仰的民间附会，
与唐代渡来无涉。

## 真相结论

杨贵妃缢死于马嵬驿有正史直接记载；「东渡日本」是文学想象与民间信仰
层累而成的传说，主流史学界对其死于马嵬无异议。
````

## 九、典型错误示例（自查反面教材）

| 错误写法 | 后果 |
|---|---|
| `verdict: 已证伪` | ❌ 校验失败。必须用英文枚举 `refuted` |
| `era: 唐朝` | ❌ 校验失败。必须用 `suitang` |
| `origin: 小说` | ❌ 校验失败。须从 5 个中文值中选：文学演绎/讹传/伪史/网络新造/影视误导 |
| `text: 陈康祺. 郎潜纪闻. 北京: 中华书局, 1984: 132.` | ❌ YAML 解析失败（值内含 `: ` 未加引号）。必须 `"..."` 双引号包裹 |
| `updated: 2026/08/20` | ❌ 校验失败。必须 `YYYY-MM-DD` |
| 正文含 `[查看](https://example.com)` | ❌ 导入失败。离线铁律禁止外链 |
| 正文用 `<b>强调</b>` | ❌ 原样显示为文本。改用 `**强调**` |
| 缺 `## 真相结论` 区块 | ❌ 校验失败 |
| `## 一、谣言溯源` | ❌ 标题不识别（多了「一、」）。必须逐字 `## 谣言溯源` |
| `tags: [1421]` | ⚠️ 会存成数字。改 `["1421"]` |
| 虚构书名/页码凑参考文献 | ❌ 违反信条。宁可删掉整条论证 |

## 十、产出前自检清单（逐项打勾后再输出）

```
□ 文件名 = id + .md，id 为 kebab-case 且不含大写/下划线
□ front-matter 12 个字段齐全，无多余字段
□ verdict/era/category/origin/evidence 全部取自受控词表原值
□ title ≤ 60 字；rumor ≤ 300 字且是谣言原始陈述
□ updated 为 YYYY-MM-DD；revision 与修订次数一致（新文件为 1）
□ references ≥ 1 条，text 全部双引号包裹、GB/T 7714 或古籍引法、无 URL
□ ref id 无重复，惯例 ref1/ref2 递增
□ 正文含 ## 谣言溯源、## 史料考证、## 真相结论（## 流传脉络 可选）
□ 四个区块标题逐字正确，无其他二级标题
□ 每个 [^refN] 都对应存在的 reference id；每条 reference 都被引用过
□ 全文零 http/https 链接、零 raw HTML
□ 结论评级与证据强度匹配，无虚构文献，语气档案式
```

## 附：导入与更新流程（供 AI 理解文件去向）

1. **新卷宗**：写好 md → 应用「导入管理」页拖入 → 校验通过即入馆（存于浏览器 IndexedDB），不影响任何既有内容；或放入项目 `content/` 目录重新构建，成为内置卷宗。
2. **修订既有卷宗**：复制原 md → 修改内容 → `revision` **加 1** → `updated` 改为当日 → 拖入导入。
   - 新版 revision **更高** → 自动覆盖生效，挂「本地修订」徽章；
   - revision **相同或更低** → 弹出三选裁决（覆盖导入 / 保留本馆 / 查看两版差异）。
3. 转正闭环：导入层任何卷宗可在「导入管理」导出为 md，放入 `content/` 重新构建即成为内置内容。
